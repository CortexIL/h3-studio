# Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clips belong to projects instead of to one person. You open a project and see its studio and its finished clips, and you can add other people as viewers or editors.

**Architecture:** Two new tables, `projects` and `project_members`, plus a `jobs.project_id` column. A migration puts every existing clip into a "My clips" project owned by whoever made it. Access to a clip depends on membership in the clip's project, so `jobs.get_for` joins the membership table and returns the caller's role. Each route then asks for one of three rights: `view`, `make` or `manage`. List endpoints take an optional `?project=<id>`, which one dependency (`project_scope`) checks. Without that parameter they behave exactly as they do today, so browser tabs opened before the deploy keep working. The React client reads the project id from the URL (`/p/:projectId`) inside the data hooks, so most components need no new props.

**Tech Stack:** FastAPI, psycopg 3 / Postgres, pytest (real Postgres); React 19, TypeScript, react-router 8, TanStack Query, zustand, shadcn/ui, MSW, vitest.

**Spec:** `docs/superpowers/specs/2026-11-21-projects-design.md`

## Global Constraints

- Roles are exactly `owner`, `editor` and `viewer`. The interface labels are "Owner", "Can make videos" and "Can watch" (Hebrew: "בעלים", "יכול/ה ליצור סרטונים", "יכול/ה לצפות").
- Rights: `view` = any member. `make` = `owner` or `editor`. `manage` a clip = the clip's maker (`jobs.user_id`), or the project's `owner`. Project settings and people are owner-only.
- A non-member gets **404** for a project and for every clip in it. A member who lacks the right gets **403**.
- Invites go only to existing accounts, by email (matched with `users._norm`). An unknown or disabled email gets 404 with the text `Nobody has an H3 account with that email.`
- A project name is trimmed and must be 1–80 characters.
- The migration's project name is exactly `My clips`.
- A request without `project` behaves exactly as today. `POST /api/jobs` and `POST /api/inbox/upload` without `project` put clips in `projects.personal_for(caller)`.
- Fair-share queue order stays keyed on `jobs.user_id`. Do not touch `_turn`, `_FAIR_CTE`'s partitioning or `claim_next_queued` ordering.
- Every new `/api` route carries `Depends(current_user)` explicitly (`tests/test_isolation.py::test_every_api_route_requires_a_session` walks them).
- Every new interface string goes in both `frontend/src/i18n/en.ts` and `he.ts`, in plain words with no AI jargon (`i18n.test.tsx` checks the two files match).
- Prompts and emails are React text only. Never `dangerouslySetInnerHTML`, `alert`, `confirm` or `prompt`; use `useConfirm` and toasts.

## Review Focus

1. **A teammate opens a clip that has a reference picture.** `/api/image/<key>` checks only the caller's own `uploads/<id>/` prefix, so teammates would see broken thumbnails. Expected: members see them and strangers get 404. Pinned in Task 4 (`test_teammates_see_reference_pictures_strangers_do_not`).
2. **The owner deletes an editor's clip.** `delete_for(user_id, …)` is scoped by maker, so passing the owner's id silently deletes nothing. Expected: the clip and its files are gone. Pinned in Task 4 (`test_the_owner_deletes_an_editors_clip_and_its_file`).
3. **A removed member's tab keeps polling.** Expected: 404 on the project, its feed and its clip ids, with no leftover access through a clip id. Pinned in Task 3 (`test_a_removed_member_loses_the_project_and_its_clips`).
4. **Deleting a project while a clip renders on the GPU.** Expected: 409, and nothing is deleted. Pinned in Task 3 (`test_a_busy_project_cannot_be_deleted`).
5. **A browser tab from before the deploy queues a clip** (no `project` param). Expected: the clip lands in "My clips", and a "My clips" project is created if there was none. Pinned in Task 4 (`test_a_clip_sent_without_a_project_lands_in_my_clips`).

**Interfaces:**
- Produces (`app/store/projects.py`):
  - `ROLES = ("owner", "editor", "viewer")`, `MAKERS = ("owner", "editor")`, `PERSONAL_NAME = "My clips"`
  - `async def create(owner_id: str, name: str) -> dict` → `{id, name, created_at}`. The project row and the owner's membership are inserted in one transaction.
  - `async def get_for(user_id: str, project_id: str) -> dict | None` → `{id, name, created_at, my_role}`. Returns `None` if the caller is not a member or `project_id` is not a UUID (check with `uuid.UUID` before querying).
  - `async def list_for(user_id: str) -> list[dict]` → `{id, name, my_role, members: int, clips: int, last_clip_at: float | None, cover_job_id: str | None}`, newest activity first (`GREATEST(last clip created_at, project created_at) DESC`). `cover_job_id` is the newest `done` clip that has a `poster_key`.
  - `async def rename(project_id: str, name: str) -> None`
  - `async def delete(project_id: str) -> None` (cascades to jobs and members)
  - `async def busy(project_id: str) -> bool`: True if any job is `queued` or `running`
  - `async def files_of(project_id: str) -> list[str]`: every non-null `output_key` and `poster_key` in the project
  - `async def members(project_id: str) -> list[dict]` → `{user_id, email, role, avatar_key}`, owner first, then by `added_at`
  - `async def add_member(project_id: str, user_id: str, role: str) -> bool`: False if already a member (`ON CONFLICT DO NOTHING`)
  - `async def set_role(project_id: str, user_id: str, role: str) -> bool`
  - `async def remove_member(project_id: str, user_id: str) -> bool`
  - `async def personal_for(user_id: str) -> str`: id of the oldest project this user owns, or a new `My clips` one if they own none. Serialized with `pg_advisory_xact_lock(hashtext('personal:' || %s))` inside the transaction.
  - `async def share_a_project(a: str, b: str) -> bool`
- Produces (`app/store/jobs.py`): `COLUMNS` gains `project_id::text AS project_id`. `add(user_id, prompt, *, project_id: str | None = None, …)` stores `project_id`, and `None` means `await projects.personal_for(user_id)`.

```sql
CREATE TABLE IF NOT EXISTS projects (
    id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name       TEXT NOT NULL CHECK (char_length(name) BETWEEN 1 AND 80),
    created_by UUID REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE IF NOT EXISTS project_members (
    project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    user_id    UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role       TEXT NOT NULL CHECK (role IN ('owner','editor','viewer')),
    added_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (project_id, user_id)
);
CREATE INDEX IF NOT EXISTS idx_project_members_user ON project_members (user_id);
ALTER TABLE jobs ADD COLUMN IF NOT EXISTS project_id UUID REFERENCES projects(id) ON DELETE CASCADE;
-- One "My clips" per person who has clips; everyone else starts with none.
INSERT INTO projects (name, created_by)
    SELECT 'My clips', u.user_id FROM (SELECT DISTINCT user_id FROM jobs) u;
INSERT INTO project_members (project_id, user_id, role)
    SELECT id, created_by, 'owner' FROM projects;
UPDATE jobs SET project_id = p.id FROM projects p WHERE p.created_by = jobs.user_id;
ALTER TABLE jobs ALTER COLUMN project_id SET NOT NULL;
CREATE INDEX IF NOT EXISTS idx_jobs_project_feed ON jobs (project_id, created_at DESC)
    WHERE dismissed_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_jobs_project_archive ON jobs (project_id, finished_at DESC)
    WHERE status = 'done';
```
